## 1. مقدمة

### 1.1 الغرض من الوثيقة

تهدف هذه الوثيقة إلى تحديد المتطلبات الوظيفية وغير الوظيفية لنظام 8xCRM، وهو نظام لإدارة علاقات العملاء (CRM) موجّه للقطاع العقاري، بالاستناد إلى المواصفات والشاشات الحالية للنظام. تُستخدم هذه الوثيقة كمرجع أساسي لفريق التطوير لبناء المرحلة الأولى من المشروع.

### 1.2 نظرة عامة على النظام

نظام 8xCRM هو منصة متكاملة لإدارة العملاء المحتملين (Leads) والصفقات (Deals) والمخزون العقاري (Inventory) والحملات التسويقية (Marketing)، تتيح لفرق المبيعات العقارية متابعة العملاء من التواصل الأول وحتى إتمام الصفقة، مع أدوات تقارير وإحصائيات وإجراءات جماعية (Bulk Actions) لإدارة أعداد كبيرة من الليدز بكفاءة.

### 1.3 نطاق المشروع

يغطي نطاق المرحلة الأولى من المشروع بناء الواجهات الأمامية (Front-End) للشاشات والوحدات الموضحة في هذه الوثيقة، باستخدام HTML وCSS وJavaScript فقط دون إطار عمل خارجي، بهدف التحقق من تجربة المستخدم وتدفق الشاشات قبل الانتقال إلى مرحلة الربط بقاعدة بيانات/واجهة خلفية.

### 1.4 التعريفات والاختصارات

| المصطلح | الوصف |
|---------|-------|
| Lead / عميل محتمل | شخص أبدى اهتمامًا بوحدة عقارية ويتم تتبعه داخل النظام. |
| Deal / صفقة | عملية بيع أو تعاقد قيد التنفيذ مرتبطة بعميل محتمل. |
| Stage / مرحلة | المرحلة الحالية للعميل المحتمل ضمن مسار المبيعات. |
| Bulk Actions / إجراءات جماعية | تنفيذ إجراء واحد على عدد من الليدز في آن واحد. |
| Check-in / Check-out | تسجيل حضور وانصراف الوكيل عند زيارة ميدانية للعميل. |
| Wallet / محفظة | تصنيف تنظيمي لمجموعة ليدز ضمن النظام. |

## 2. المستخدمون والأدوار

يوضح الجدول التالي الأدوار الرئيسية المتوقعة في النظام ومستوى الصلاحيات لكل دور، على أن تُفعَّل الصلاحيات الفعلية (تحقق/تفويض) في مرحلة لاحقة بعد الربط بالخادم:

| الدور | الصلاحيات |
|-------|-----------|
| مدير النظام (Admin) | صلاحية كاملة: عرض جميع التقارير والإحصائيات، إدارة الوكلاء والفرق، تنفيذ الإجراءات الجماعية، إدارة المخزون والحملات، الوصول لكافة شاشات التصدير. |
| مشرف الفريق (Team Leader) | عرض وإدارة بيانات فريقه فقط: متابعة أداء الوكلاء التابعين له، عرض التقارير الخاصة بفريقه، تنفيذ إجراءات جماعية على ليدز فريقه. |
| الوكيل (Agent) | عرض وإدارة الليدز الخاصة به فقط: قائمة المهام، الأحداث والاجتماعات، تسجيل الدخول/الخروج الميداني، تحديث حالة الليدز، عرض تقاريره الشخصية. |

## 3. المتطلبات الوظيفية (Functional Requirements)

تم تقسيم المتطلبات الوظيفية إلى وحدات (Modules) مطابقة لوحدات النظام الحالية، وتم تمييز المتطلبات الجديدة المطلوب إضافتها بعبارة **[ميزة جديدة مطلوبة]**.

### RF-01 الشريط العلوي والتقارير العامة (Top Bar & Reports)

- **RF-01.1** يعرض النظام في الشريط العلوي اسم النظام (8xCRM) مع أيقونة قائمة (ثلاث نقاط أفقية).
- **RF-01.2** عند النقر على أيقونة القائمة تظهر قائمة منسدلة تضم: التقارير (Reports)، إحصائيات الوكلاء (Agent Statistics).
- **RF-01.3** تتيح شاشة إحصائيات الوكلاء الفلترة حسب المجموعة (Group) والوكيل (Agent).
- **RF-01.4** تتيح الشاشة الفلترة حسب نطاق تاريخ الإنشاء (Creation Range) ونطاق تاريخ آخر تحديث (Last Updated Range).
- **RF-01.5** يوفر النظام نموذج تقرير منفصل يعرض عمل الوكيل اليومي التفصيلي (Agent's Day Work).

### RF-02 الأحداث (Events)

- **RF-02.1** يعرض النظام جميع الأحداث المجدولة (اجتماعات وأنواع الإجراءات - Meeting Types).
- **RF-02.2** تتيح الشاشة الفلترة حسب: المنشئ (Creator)، الحاضرين (Attendees)، نوع الحدث (Event Type)، نطاق التاريخ (Date Range).
- **RF-02.3** يمكن فلترة الأحداث المنتهية فقط (Done) لعرض الاجتماعات المكتملة.
- **RF-02.4** تتيح الشاشة فلترة اختيارية حسب المدينة (City).
- **RF-02.5** يوفر النظام زر (إعادة تعيين - Reset) لمسح جميع الفلاتر المُدخلة.
- **RF-02.6** يوفر النظام زر (تطبيق وتصدير - Apply & Export) لتطبيق الفلاتر وتصدير النتائج.
- **RF-02.7** تعرض نتائج الأحداث بيانات العميل المحتمل (Lead) المرتبط بالإجراء المكتمل، متضمنة: التاريخ، المصدر، الوكيل.
- **RF-02.8** تعرض النتائج اسم العميل المحتمل ورقم هاتفه.
- **RF-02.9** عند النقر على أي سجل حدث ينتقل النظام مباشرة إلى صفحة تفاصيل العميل المحتمل (Lead Profile).

### RF-03 التصدير (Export)

- **RF-03.1** يتيح النظام تصدير (رفع) البيانات من الـCRM بصيغة قابلة للطباعة.
- **RF-03.2** توفر شاشة طلبات التصدير (Export Request) فلاتر لمعرفة من قام بالإجراء، وتاريخه، والمصدر، والاهتمام (Interest)، وغيرها.
- **RF-03.3** يعرض جدول طلبات التصدير الأعمدة التالية: اسم الملف، نوع التصدير، عنوان IP الخاص بعملية التصدير، التاريخ، بواسطة (اسم المستخدم)، ونوع الليدز المُصدَّرة.
- **RF-03.4** توفر كل صف في الجدول أيقونات لرفع (Upload) أو حذف (Delete) ملف التصدير.

### RF-04 لوحة التحكم (Dashboard)

- **RF-04.1** تتيح لوحة التحكم اختيار فريق ووكيل معيّن (مثال: فريق خالد - الوكيلة أميرة) لعرض إجمالي عدد الليدز الخاصة بهم موزّعة على المراحل (Stages).
- **RF-04.2** يوفر قسم (اختيار اللوحة - Dashboard Selection) خيارات تصفية جميع الليدز حسب: التصنيف (دافئ Warm / بارد Cold / الكل All)، الفريق (Team)، والوكيل (Agent).
- **RF-04.3** تعرض اللوحة جميع مراحل رحلة العميل المحتمل (Stages) مرتّبة أسفل بعضها البعض مع عدد الليدز في كل مرحلة.
- **RF-04.4** يعرض أسفل اللوحة قسم (النشاط الأخير للمكالمات - Recent Activity Calls).
- **RF-04.5** عند النقر على قسم النشاط الأخير تُعرض تفاصيل الأنشطة الأخيرة لكل عميل محتمل، متضمنة إجراء المكالمة (Call Action) والملاحظات (Feedback).
- **RF-04.6** يوفر قسم النشاط الأخير شريط بحث (Search Bar)، واسم الوكيل، وتاريخ ووقت النشاط.

### RF-05 الملف الشخصي وأفضل الوكلاء (Profile & Top Agents)

- **RF-05.1** يعرض قسم الملف الشخصي: تاريخ الانضمام، صورة المستخدم، والمسمى الوظيفي (Title).
- **RF-05.2** يعرض قسم (أفضل الوكلاء - Top Agents) ترتيب الوكلاء الأعلى أداءً.
- **RF-05.3** يوفر النظام زرًا (+) لإضافة عنصر جديد مرتبط بالملف الشخصي.
- **RF-05.4** يعرض النظام النقاط (Points) المكتسبة لكل وكيل ضمن ملفه الشخصي.

### RF-06 قائمة المهام (Todo's)

- **RF-06.1** عند النقر على قائمة المهام تظهر خيارات الإجراء: متابعة (Follow up) أو جدولة اجتماع (Schedule Meeting).
- **RF-06.2** عند اختيار (المتابعات المتأخرة - Delay) يعرض النظام جميع المتابعات المتأخرة لكل الوكلاء باستثناء المستخدم الحالي (كمثال: 130 متابعة متأخرة).
- **RF-06.3** يوفر النظام فلتر (نوع الاستحقاق - Due Type) بخيارات: متأخر (Late/Delay)، اليوم (Today)، غدًا (Tomorrow)، القادم (Upcoming)، المكتمل (Completed).
- **RF-06.4** يوفر النظام فلتر (المسؤولون عن المتابعة - Follow ups Assignees/Attendees) بخيارات: الكل (All)، أنا فقط (Only Me)، الآخرون فقط (Only Other - جميع المستخدمين باستثناء المستخدم الحالي)، ومخصّص (Custom) لاختيار وكيل بعينه.
- **RF-06.5** يوفر النظام شريط بحث (Search) للبحث باسم العميل المحتمل، رقم الهاتف، أو اسم الوكيل.
- **RF-06.6** عند النقر على أي عنصر في قائمة المهام ينتقل النظام إلى صفحة العميل المحتمل الكاملة (كل المعلومات والسجل التاريخي).

### RF-07 التقارير التفصيلية (Reports)

- **RF-07.1** يوفر النظام تقرير (نظرة عامة - Overall) يتيح اختيار يوم محدد أو نطاق تاريخ، ويعرض إحصائيات شاملة (مكالمات، اجتماعات، مهام، رسائل، وغيرها).
- **RF-07.2** يوفر النظام تقرير (الوكيل - Agent Report) يتيح اختيار تاريخ أو نطاق تاريخ ووكيل معيّن (مثال: أميرة) ويعرض كافة أنشطته على النظام.
- **RF-07.3** يوفر النظام تقرير (سجلات المكالمات - Call Logs) يعرض جميع سجلات المكالمات على مستوى النظام.
- **RF-07.4** يوفر النظام تقرير (مدة المكالمات - Call Duration) بفلتر نطاق تاريخ، يعرض جميع مستخدمي النظام مع مدة كل مكالمة.
- **RF-07.5** يوفر النظام تقرير (يوم العمل - Day Work) بفلتر نطاق تاريخ، يعرض جميع الوكلاء مع توقيت تنفيذ كل إجراء لتحديد ساعات الذروة لكل وكيل.
- **RF-07.6** يوفر النظام تقرير (الأداء - Performance) يتيح اختيار نطاق زمني، وعند النقر على وكيل معيّن يُعرض تقرير أداء تفصيلي إضافي يضم مجموعة إحصائيات.
- **RF-07.7** يوفر النظام تقرير (الاجتماعات - Meetings) يتيح الفلترة حسب المنشئ (Creator) والوكيل (Agent).
- **RF-07.8** يوفر النظام تقرير (الليدز - Leads Report) يعرض إحصائيات شاملة: الليدز حسب المرحلة، الليدز حسب المصدر، المصدر حسب الاهتمام، الليدز حسب الاهتمام، مع فلتر نطاق تاريخ.

### RF-08 الصفقات (Deals)

- **RF-08.1** يوفر النظام شاشة (رؤى الصفقات - Deals Insights) تعرض تحليلات عامة على الصفقات.
- **RF-08.2** تعرض الشاشة قائمة بكل إجراء صفقة جديد قام به الوكيل، مرتبطًا بالعميل المحتمل (Lead) الخاص به.
- **RF-08.3** توفر الشاشة فلاتر تساعد في إعداد التقارير أو البحث عن عميل محتمل أو إجراء تحليل.
- **RF-08.4** يجب أن يوفر النظام إمكانية إضافة إجراء لإغلاق الصفقات القديمة (Close Old Deals) بحالة: مغلقة - خسارة (Closed Lost) أو مغلقة - ربح (Closed Won).

### RF-09 المخزون (Inventory)

- **RF-09.1** يوفر النظام قسمًا لإدارة تفاصيل الوحدة (Unit Details) يتيح التعديل والتحديث والحذف.
- **RF-09.2** يوفر النظام إمكانية إنشاء رابط نشر (Publish Link) بعد تعبئة كافة تفاصيل الوحدة (Create Publish Time).
- **RF-09.3** يمكن إرسال رابط النشر إلى العميل مباشرة أو نشره على فيسبوك بهدف توليد عملاء محتملين (Leads) من خلال نموذج (تواصل معنا - Get in Touch).
- **RF-09.4** عند تعبئة العميل لنموذج التواصل عبر رابط النشر، يُوجَّه تلقائيًا وتُنشأ بياناته كعميل محتمل داخل الـCRM.
- **RF-09.5** يوفر النظام آلية لإضافة وحدة جديدة عبر اختيار نوع الوحدة ثم تعبئة بياناتها.
- **RF-09.6** يوفر النظام بحثًا متقدمًا بالفلاتر للوصول إلى أي وحدة مخزون.

### RF-10 التسويق (Marketing)

- **RF-10.1** يعرض النظام قائمة بجميع الحملات التسويقية (Campaigns).
- **RF-10.2** توفر الشاشة شريط بحث (Search Bar) وفلاتر (Filters) للحملات.
- **RF-10.3** يوفر النظام زر (حملة جديدة - New Campaign) لإنشاء حملة تسويقية جديدة.

### RF-11 تسجيل الدخول والخروج الميداني (Check-in / Check-out)

- **RF-11.1** يعرض النظام جميع عمليات تسجيل الدخول (Check-in) والخروج (Check-out) المرتبطة بكل عميل محتمل.
- **RF-11.2** تتيح هذه البيانات معرفة موقع ووقت اجتماع الوكيل مع العميل.
- **RF-11.3** عند النقر على عملية تسجيل دخول تُعرض التفاصيل التالية: الموقع (Location)، التاريخ والوقت، اسم الوكيل، وصورة توثيقية.

### RF-12 مساحة العمل (Workspace)

- **RF-12.1** توفر مساحة العمل وصولًا سريعًا للمهام حسب: متأخر (Late)، اليوم (Today)، غدًا (Tomorrow)، القادم (Upcoming).
- **RF-12.2** يوفر النظام إمكانية تحديد (الكل) أو (لا شيء) من قائمة المهام المعروضة، وكذلك تحديد عناصر بعينها.
- **RF-12.3** يوفر النظام إحصائية إجمالية للإجراءات المتأخرة (مثال: ما يقارب 150 إجراء متأخر).
- **RF-12.4** يوفر النظام خاصية إرسال رسائل SMS إلى عدد مُحدَّد من العملاء المحتملين (Leads) دفعة واحدة.

### RF-13 الإجراءات الجماعية (Bulk Actions)

- **RF-13.1** يتيح النظام تنفيذ إجراء واحد على عدد كبير من الليدز في آن واحد (إضافة أو إزالة): الاهتمامات (Interests)، الوسوم (Tags)، الحملة (Campaign)، قائمة الليدز (Lead List)، المحافظ (Wallets)، والتقييمات (Ratings).
- **RF-13.2** إعادة التعيين (Reassign): إمكانية إعادة تعيين مجموعة من الليدز لوكيل آخر دفعة واحدة.
- **RF-13.3** إخفاء السجل (Hide History) لمجموعة محددة من الليدز.
- **RF-13.4** تغيير المرحلة (Change Stage) لمجموعة من الليدز دفعة واحدة.
- **RF-13.5** إضافة وسوم (Tags) لمجموعة من الليدز.
- **RF-13.6** إضافة مهام (Add Tasks): تحديد عدد من الليدز لإنشاء مهمة جديدة تذكّر الوكيل بالمتابعة أو اتخاذ إجراء.
- **RF-13.7** تغيير التقييم (Change Rating): دافئ (Warm) / ساخن (Hot) / بارد (Cold).
- **RF-13.8** تغيير المصدر (Change Source) لمجموعة من الليدز.
- **RF-13.9** تغيير المحفظة (Change Wallet) لمجموعة من الليدز.
- **RF-13.10** إضافة ملاحظة جماعية (Add Bulk Note).
- **RF-13.11** دمج الليدز (Merge Leads) للتعامل مع الليدز المكررة (إجراء نادر الاستخدام كعملية جماعية).
- **RF-13.12** حذف جماعي (Bulk Delete) لمجموعة من الليدز.
- **RF-13.13** **[ميزة جديدة مطلوبة]** زر (تحديد جميع المهام كمكتملة - Mark all Todo's as Complete): يتيح اختيار سبب (مثال: عدم رد الوكيل X) ثم تنفيذ الإغلاق الجماعي للإجراءات المتأخرة على المراحل غير المحتملة أو التي أُدخلت بشكل غير صحيح من قِبل الوكيل.
- **RF-13.14** **[ميزة جديدة مطلوبة]** إجراء التراجع (Undo Action): يجب أن يحتفظ النظام بسجل للإجراءات الجماعية المنفَّذة، مع إمكانية التراجع عنها (Undo).
- **RF-13.15** **[ميزة جديدة مطلوبة]** إشعار/تنبيه جماعي (Bulk Nudge): إمكانية تحديد عدد من الليدز وإرسال تنبيه جماعي (Nudge) يظهر للوكيل كمهمة أو متابعة تستوجب اتخاذ إجراء.

### RF-14 الفلاتر وشريط التصدير (Filters & Export Bar)

- **RF-14.1** توفر شاشة الفلاتر خيارات تساعد في التحليل وإعداد التقارير.
- **RF-14.2** **[ميزة مطلوبة]** إضافة فلتر (الوكيل - Agent) وفلتر (المرحلة - Stage) إلى شاشة الفلاتر.
- **RF-14.3** يوفر النظام شريط تصدير يتيح: تصدير الليدز (Export Leads)، وتصدير معلومات الليدز (Leads Info).

## 4. المتطلبات غير الوظيفية (Non-Functional Requirements)

| المتطلب | الوصف |
|---------|-------|
| الأداء (Performance) | يجب أن تُحمَّل الصفحات الرئيسية (لوحة التحكم، قائمة المهام، التقارير) خلال أقل من 3 ثوانٍ عند توفر اتصال إنترنت عادي. |
| سهولة الاستخدام (Usability) | يجب أن تكون واجهة المستخدم بسيطة ومباشرة للوكلاء غير التقنيين، مع دعم كامل للغة العربية واتجاه الكتابة من اليمين لليسار (RTL). |
| التوافق (Compatibility) | يجب أن يعمل النظام بشكل صحيح على أحدث إصدارات المتصفحات (Chrome, Edge, Safari, Firefox) وعلى الشاشات المختلفة (Desktop / Tablet). |
| الاستجابة (Responsiveness) | يجب أن تكون الواجهات متجاوبة (Responsive) بحيث تعمل بصورة مقبولة على شاشات الحاسوب والأجهزة اللوحية كحد أدنى في المرحلة الأولى. |
| الأمان (Security) | يجب تقييد الوصول إلى الوظائف حسب صلاحية المستخدم (مدير / مشرف فريق / وكيل)، وتسجيل عمليات التصدير والإجراءات الجماعية (Audit Log). |
| قابلية التوسع (Scalability) | يجب تصميم بنية الشيفرة (HTML/CSS/JS) بشكل معياري (Modular) يسهّل لاحقًا الانتقال إلى إطار عمل (Framework) أو ربط بواجهات خلفية (APIs) دون إعادة بناء كاملة. |
| إمكانية الصيانة (Maintainability) | تنظيم الملفات والأكواد بأسماء واضحة وتعليقات كافية لتسهيل الصيانة والتطوير المستقبلي. |

## 5. المتطلبات التقنية للمرحلة الأولى

بناءً على طلب صاحب المشروع، تُبنى المرحلة الأولى من هذا المشروع وفق القيود التالية:

- تُبنى المرحلة الأولى من المشروع باستخدام HTML و CSS و JavaScript الأساسي (Vanilla JS) فقط، دون استخدام أي إطار عمل خارجي (لا React، لا Vue، لا Angular) ودون مكتبات تصميم جاهزة (لا Bootstrap، لا Tailwind).
- تُستخدم بيانات وهمية (Mock Data) أو ملفات JSON محلية لعرض الشاشات والتفاعلات في هذه المرحلة، دون ربط فعلي بقاعدة بيانات أو واجهة خلفية (Backend API).
- يُبنى الهيكل باستخدام صفحات HTML منفصلة أو تبديل أقسام (Sections) عبر JavaScript، مع تنظيم الأنماط (CSS) في ملفات منفصلة حسب الوحدة/الشاشة لتسهيل القراءة.
- يُراعى في تصميم الشيفرة إمكانية الانتقال مستقبلاً (في مرحلة لاحقة) إلى إطار عمل حديث أو ربط بواجهات خلفية دون الحاجة لإعادة بناء الواجهات من الصفر.
- تُستخدم أيقونات ورموز مفتوحة المصدر (مثل Font Awesome عبر رابط CDN) عند الحاجة، دون اعتبار ذلك إطار عمل.

### هيكلية مقترحة للمشروع

يوصى بتنظيم ملفات المرحلة الأولى على النحو التالي:

- `index.html` — لوحة التحكم الرئيسية (Dashboard)
- `workspace.html` — مساحة العمل وقائمة المهام
- `leads.html` — قائمة العملاء المحتملين + صفحة تفاصيل الليد
- `deals.html` — الصفقات
- `inventory.html` — المخزون والوحدات
- `marketing.html` — الحملات التسويقية
- `reports.html` — شاشات التقارير المختلفة
- `checkin.html` — تسجيل الدخول والخروج الميداني
- `assets/css/` — ملفات الأنماط مقسّمة حسب الوحدة
- `assets/js/` — ملفات جافاسكريبت مقسّمة حسب الوحدة، وملف بيانات وهمية `mock-data.js`

## 6. خارج نطاق المرحلة الأولى

- الربط الفعلي بقاعدة بيانات أو خادم (Backend/API) — يُؤجَّل لمرحلة لاحقة من المشروع.
- تطبيقات الجوال (iOS / Android) — غير مشمولة في هذه المرحلة.
- التكامل الفعلي مع خدمات خارجية (مثل نشر الحملات على فيسبوك أو بوابات إرسال SMS الفعلية) — تُبنى الواجهة فقط بافتراض وجود هذا التكامل لاحقًا.
- نظام صلاحيات وتوثيق (Authentication/Authorization) فعلي — يُكتفى في المرحلة الأولى بواجهات تحاكي تسجيل الدخول دون تحقق حقيقي.
