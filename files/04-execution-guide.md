# 04 — دليل التنفيذ العملي مع نماذج رخيصة

## خطوات العمل اليومية

1. افتح `03-tasks.md`، اختر أول مهمة ⬜ في المرحلة الحالية غير المكتملة.
2. تأكد أن كل التبعيات المذكورة أمامها منجزة (✅) فعلًا — إن لم تكن، نفّذها أولًا.
3. جهّز الـ Prompt عبر `tasks/_template-prompt.md` (راجع `tasks/example-T108-filter-bar.md` كمرجع).
4. أرسله للنموذج الرخيص في **محادثة جديدة نظيفة** (لا تراكم سياق قديم غير ضروري — يربك النماذج الصغيرة).
5. احفظ الكود الناتج في المسار المحدد بالضبط في `02-plan.md § 1`.
6. راجع "معايير القبول" للمهمة يدويًا (افتح المتصفح فعليًا واختبر).
7. إذا فشل معيار واحد فقط: أعد صياغة نفس الـ Prompt مع إضافة سطر "الفشل السابق كان: [صف الخطأ بدقة]" واطلب إصلاحًا فقط لتلك النقطة (لا تعد كل الملف من الصفر عبر نموذج مختلف تمامًا إلا إذا فشل النموذج مرتين متتاليتين).
8. علّم المهمة ✅ في `03-tasks.md` فقط بعد اجتياز **كل** معايير القبول.

## متى تستخدم نموذجًا أقوى بدل الرخيص

استخدم نموذجًا أقوى (وليس الرخيص) في هذه الحالات فقط:
- أي تعديل على `02-plan.md` نفسه (قرارات معمارية).
- دمج/مراجعة نهائية لأي مرحلة كاملة قبل الانتقال للتالية.
- عندما يفشل النموذج الرخيص في نفس المهمة 3 مرات متتالية رغم التقسيم.
- كتابة/مراجعة منطق `store.js` و`db.js` (طبقة البيانات المركزية) — أي خطأ هنا ينتشر لكل الصفحات.

## قائمة تحقق نهائية شاملة (قبل اعتبار المشروع جاهزًا)

### وظيفي
- [ ] كل بند من B1 إلى B14 مُتحقَّق منه يدويًا حسب مصفوفة التتبع في `01-specify.md`.
- [ ] كل الـ 13 عملية جماعية تُنفَّذ فعليًا وتُغيّر البيانات الحقيقية (وليست console.log فقط).
- [ ] التصدير بالصيغ الأربع (CSV/Excel/PDF/JSON) ينتج 4 ملفات مختلفة فعليًا يمكن التحقق من محتواها.
- [ ] الرابط العام لوحدة عقارية يعمل من نافذة تصفح خاصة بدون أي بيانات جلسة سابقة، ويُنشئ Lead جديدًا عند الإرسال.
- [ ] التراجع (Undo) يعيد القيم الدقيقة السابقة، وليس فقط "يزيل" السجل.

### تقني
- [ ] لا استدعاء مباشر لـ IndexedDB/localStorage خارج `js/data/store.js` (ابحث بـ `grep -r "indexedDB" js/pages/`).
- [ ] لا `onclick=""` inline في أي ملف HTML.
- [ ] كل console فارغة من الأخطاء عند تصفح كل الصفحات الـ13.
- [ ] اختبار 1000+ سجل: التمرير سلس (Virtual Scrolling فعّال).

### تجربة المستخدم
- [ ] Toast يظهر لكل عملية (نجاح/فشل) دون استثناء.
- [ ] لا يوجد أي أيقونة أو زر بلا استجابة عند النقر (امسح كل الصفحات يدويًا وانقر كل عنصر تفاعلي).
- [ ] التجاوب يعمل فعليًا عند 1024px و768px (اختبر بـ DevTools device toolbar لا بتصغير النافذة فقط).

## أخطاء شائعة عند النماذج الرخيصة (راقبها تحديدًا)

| الخطأ الشائع | كيف تكتشفه | الحل |
|---|---|---|
| زر "تطبيق"/"حفظ" بلا `addEventListener` فعلي | ابحث بصريًا عن `addEventListener` في الملف الناتج | أعد الطلب مع التركيز صراحة على "اربط الزر فعليًا" |
| تصدير كل الصيغ بنفس المنطق (نسخ CSV بامتداد مختلف) | افتح الملفات الأربعة وقارن المحتوى الخام | اطلب صراحة استخدام SheetJS لـ Excel وjsPDF لـ PDF كما في T231/T232 |
| قراءة/كتابة مباشرة لـ IndexedDB بدل المرور عبر store.js | ابحث عن `indexedDB.open` خارج db.js | ذكّر النموذج بقاعدة "العقد الوحيد" في constitution |
| اختيار قيم افتراضية تلقائيًا في نموذج الإضافة (B5) | افتح النموذج فارغًا وتحقق أن كل select على "اختر..." | أضف صراحة "لا تضع value مبدئي لأي `<select>`" في الـ Prompt |
| نسيان توليد Lead Code عند الاستيراد الجماعي | افحص جدول leads بعد استيراد ملف تجريبي | تأكد أن T204 يستدعي `id-generator.js` وليس يترك id فارغًا |
