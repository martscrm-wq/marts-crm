# CRM SpecKit — دليل الاستخدام

هذا المجلد عبارة عن **"SpecKit"** كامل لتنفيذ مشروع نظام CRM الموضّح في مستند المتطلبات الأصلي، مُصمَّم خصيصًا ليكون قابلاً للتنفيذ بواسطة **نماذج ذكاء اصطناعي أرخص/أضعف** (مثل GPT-4o-mini, DeepSeek, نماذج محلية صغيرة...إلخ) دون الحاجة لفهم عميق أو استنتاج ضمني — كل شيء مُفكَّك إلى خطوات ذرية (atomic) واضحة الدخل/الخرج.

## فلسفة العمل (Spec-Driven Development)

النماذج الرخيصة تفشل غالبًا لأنها:
1. تحاول تنفيذ مهام كبيرة دفعة واحدة → تفقد السياق.
2. تفترض تفاصيل غير مذكورة → تُنتج كودًا غير متسق.
3. لا "تتذكر" قرارات سابقة بين الجلسات.

لذلك هذا الـ SpecKit يحل هذه المشاكل عبر:
- **تجزئة كل شيء** إلى مهام لا تتجاوز ملفًا أو ميزة واحدة.
- **تثبيت العقود (contracts)**: أسماء الحقول، بنية البيانات، أسماء الدوال — محددة سلفًا بالإنجليزية بدقة، لا مجال للاجتهاد.
- **معايير قبول صريحة (Acceptance Criteria)** لكل مهمة يمكن التحقق منها آليًا أو يدويًا.
- **قالب Prompt جاهز** لكل مهمة يُلصق مباشرة في النموذج الرخيص.

## طريقة الاستخدام مع نموذج رخيص

1. أعطِ النموذج الرخيص محتوى `00-constitution.md` **مرة واحدة في بداية كل جلسة/محادثة جديدة** (كـ System Prompt أو أول رسالة).
2. خذ مهمة واحدة فقط من `03-tasks.md` في كل مرة (لا تدفع عدة مهام معًا).
3. استخدم القالب الجاهز في `tasks/` المطابق لرقم المهمة — الصقه كما هو.
4. بعد التنفيذ، راجع "معايير القبول" الخاصة بالمهمة يدويًا قبل الانتقال للتالية.
5. إذا فشل النموذج الرخيص في مهمة، لا تكبّرها — قسّمها بنفسك إلى نصفين واطلب كل نصف على حدة.
6. لا تسمح للنموذج بالانتقال لمهمة تالية قبل اجتياز معايير قبول المهمة الحالية — هذا يمنع "تراكم الأخطاء".
